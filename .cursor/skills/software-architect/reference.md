# Software architect — шаблон плана и чеклист

## Шаблон артефакта (копируй структуру)

```markdown
# Дизайн: {название фичи}

## 1. Цель
{1–3 предложения от роли заказчика}

## 2. Сценарии
| Кто | Действие | Результат |

## 3. As-is
- Файлы / сервисы / UI
- Чего не хватает

## 4. To-be
### 4.1 Сервисный слой
- Новый / расширяемый класс: …
- Входы / выходы (DTO shape)

### 4.2 API / Inertia
- Маршруты, query params
- Когда считать тяжёлые props (tab / only / JSON)

### 4.3 UI
- Страница / вкладки / фильтры
- Состояния пусто / нули видны?

### 4.4 Данные и даты
| Метрика / сущность | Правило периода / снимок |

## 5. Границы
**В scope:** …
**Вне scope:** …

## 6. RBAC
- Areas / scopes
- IDOR-кейсы в тестах

## 7. Фазы
1. MVP …
2. Next …
3. Later …

## 8. Приёмка
1. …
2. …

## 9. Тесты
- Feature: …
- Unit: …
- Регрессия: …

## 10. Открытые вопросы
1. …
```

## Чеклист перед сдачей плана

- [ ] Найдены соседние паттерны (не greenfield без причины)
- [ ] Один канон на concern (нет «и сервис A, и сервис B считают одно»)
- [ ] Оси времени разведены (snapshot ≠ period), если обе нужны
- [ ] Фильтры людей/отдела пересекаются с visibility
- [ ] Нулевые строки / пустой scope оговорены
- [ ] Фаза 1 реально судоходна без фазы 2
- [ ] PHPUnit-кейсы названы
- [ ] Mermaid только если упрощает (фильтры → режимы → DTO)

## Эталон из практики CRM v5

Отчёт «Менеджеры» (`ManagerTeamReportService` + `ManagerTeamMetricCatalog`):

- Отдельный сервис, не раздувание `FinancialReportsService`
- Три режима: `snapshot` / `period` / `compare`
- Каталог метрик + группы для UI
- Условный расчёт props только на нужной вкладке
- Закрытая маржа — только через `CompletedOrderFinancialAnalytics`
- Drill-down — отдельный JSON endpoint + модалка

## Связь с rdudov 04

Полный шаблон rdudov (`agents/rdudov/04_architect_prompt.md`) — для крупных greenfield-систем. В CRM v5 **сжимай** до: компоненты, зависимости, модель данных (если новые таблицы), интерфейсы (DTO/routes), фазы. Не генерируй 20-страничный enterprise doc без запроса.
