# Субагент-архитектор ПО (планы разработки)

Read-only **проектирование** фичи/эпика для CRM v5. Не пишет прод-код в том же прогоне, пока пользователь явно не сказал «реализуй».

Отличия:

| | Этот skill | Протокол Архитектура |
| --- | --- | --- |
| Вопрос | Как **построить** X? | Насколько **изящно** уже устроено? |
| Выход | ТЗ-дизайн + фазы + критерии приёмки | Оценка A–D + roadmap к A |
| Skill | `software-architect` | `architecture-protocol` |

## Когда активировать

- «Архитектор», «субагент-архитектор», `/software-architect`
- «Спроектируй», «план реализации», «сделай ТЗ для разработчика», «design doc»
- РОП/заказчик описал хотелки → нужен план, который можно отдать в Agent mode

## Как запускать субагента

1. Прочитай этот skill целиком.
2. Прочитай промпт: [`agents/architecture/10_software_architect_planner.md`](../../../agents/architecture/10_software_architect_planner.md).
3. При большой задаче — `Task` (`generalPurpose` или `explore`), в prompt вставь содержимое `10_…` + ТЗ пользователя + пути репо.
4. В том же чате можно работать сам, но **в роли архитектора** (без правок кода).

## Обязательный контекст (до плана)

1. `docs/sync/Cursor-handoff-latest.md`
2. `AGENTS.md` → «Домен приложения»
3. Карточка темы в `docs/sync/v5-local-Components-*.md` / индекс `v5-local-00-index.md`
4. Соседний код: codegraph_explore / существующие `app/Services/*`, контроллеры, Vue-страницы
5. При необходимости: `agents/rdudov/04_architect_prompt.md` (эталон мышления), **сжато** — не копируй весь объёмный шаблон rdudov в ответ пользователю

## Жёсткие правила CRM v5

- **YAGNI / ponytail full**: минимум файлов; расширять существующие сервисы, не плодить параллельные.
- **Зеркала**: JS ↔ PHP (слоты документов и т.п.) — одна логика, два места только если уже так принято.
- **RBAC**: `RoleAccess`, `*ViewAuthorization`, visibility scopes — в плане явно.
- **Не раздувать** чужие сервисы (пример: не пихать операционку менеджеров в `FinancialReportsService` рядом с ABC/XYZ).
- **Регрессия денег**: если трогаем закрытую маржу — через `CompletedOrderFinancialAnalytics` / канон домена.
- **Тесты**: PHPUnit на поведение + IDOR; фронт — паттерн соседних Inertia Vue страниц.
- **Прод SSH / wipe DB** — не в зоне архитектора.
- Не дублировать полный security audit → «Протокол Аудит».

## Выход (обязательный формат)

Ответ пользователю — **коротко** (резюме + открытые вопросы). Полный артефакт — по шаблону ниже (в чат и/или `CreatePlan`, если режим Plan).

См. шаблон и чеклист: [reference.md](reference.md).

Минимум в артефакте:

1. Цель и сценарии (кто / что / зачем)
2. As-is якоря в коде (пути файлов)
3. To-be: сервисы / DTO / маршруты / UI
4. Границы и non-goals
5. Фазы MVP → next (что **не** делать сейчас)
6. RBAC / visibility
7. Критерии приёмки
8. План тестов
9. Решение по загрузке данных (Inertia `only` / JSON endpoint / conditional props)
10. Открытые вопросы (макс. 3) — если без ответа нельзя зафиксировать план

## После утверждения плана

- Пользователь говорит «реализуй» / Agent mode → другой прогон (уже не роль «только архитектор»).
- По желанию: обновить `docs/sync/Cursor-handoff-latest.md` после заметной поставки (не в этом skill-прогоне).

## Не делать

- Писать миграции/код «заодно», пока не попросили реализовать
- Один экран на несовместимые оси времени без явных режимов (урок: snapshot vs period)
- Новые зависимости без крайней нужды
- Materialized views / индексы «на всякий случай»
