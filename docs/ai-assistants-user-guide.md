# Ассистенты CRM — инструкция для пользователя

Руководство по **command bar** (нижняя панель CRM): персоны ассистентов, вложения, типовые сценарии и ограничения.

**См. также:** [Мастер заказов](order-wizard-user-guide.md) · [Документы](documents-user-guide.md) · [Регламент оформления заявки и изменения условий](order-application-basic-terms-regulation.md)

---

## 1. Где находится ассистент

1. Внизу экрана CRM — **command bar** (поле ввода, кнопка отправки, выбор персоны).
2. Нажмите на поле или иконку ассистента — откроется панель диалога.
3. Выберите **персону** (Джарвис, Галя, Юрик, Страж) — от неё зависят тон ответа и приоритеты, но не «жёсткая изоляция» инструментов.

> Ассистент видит только то, что доступно **вашей роли** в CRM. Если нет области «Заказы», он не откроет чужой заказ; если нет «Настройки системы» — не сохранит глобальные базовые условия напрямую.

---

## 2. Персоны (кого выбрать)

| Персона | Для чего | Типовые запросы |
| --- | --- | --- |
| **Джарвис** | Универсальный помощник | Навигация, заказы, задачи, справочники, «куда нажать» |
| **Галя** | Коммерция и продажи | Лиды, заказы, Книга продаж, тренажёр, заявка из текста/файла, КП |
| **Юрик** | Договоры и печатные формы | Базовые условия cp/dp, шаблоны DOCX, формулировки, согласование условий контрагента |
| **Страж** | Служба безопасности | Проверка контрагентов, scoring, риски (не блокирует операции сам) |

Персона **не заменяет** живого юриста, финансового контролёра или руководителя — даёт черновик, подсказку или собирает данные из CRM.

## 3. Как задать вопрос

### 3.1. Текст

- Пишите **конкретно**: номер заказа, имя контрагента, что нужно сделать («создай черновик заявки», «покажи документы заказа 12345»).
- Можно ссылаться на контекст предыдущих реплик в том же чате (история хранится в **браузере** на этом компьютере).

### 3.2. Память диалога и «Расширить память»

| Что | Как работает |
| --- | --- |
| **Хранение** | Последние реплики сохраняются в localStorage; другой браузер или устройство — отдельная история |
| **Окно для модели** | В запрос к AI уходит только **хвост** диалога (не вся лента на экране) — чтобы ответ оставался точным и быстрым |
| **Лимиты по роли** | Обычный пользователь: до **20** реплик в запросе, **10** в контексте LLM; руководитель — **40** / **20**; администратор — **100** / **50** |
| **Расширить память** | Переключатель в панели ассистента **удваивает** лимиты (доступен не администраторам — у них уже максимум) |
| **Очистить** | Кнопка сброса истории — если диалог «уплыл» или нужен чистый контекст |

При длинных цепочках (много заказов подряд) кратко напоминайте номер заказа или контрагента в новой реплике.

### 3.3. Вложения (скрепка)

К сообщению можно приложить **до 3 файлов** (PDF, DOCX и другие форматы, из которых CRM извлекает текст):

1. Нажмите **скрепку** рядом с полем ввода.
2. Выберите файл(ы).
3. Допишите текст: что сделать с содержимым («оформи заявку», «сравни с нашими условиями перевозчика»).

**Важно:**

- Из вложения извлекается **текст**, не «картинка как есть». Скан без текстового слоя может не прочитаться — тогда вставьте текст вручную или используйте «Заполнить из заявки» в мастере заказа (с OCR на сервере).
- Длинный текст **обрезается** (лимит символов для ассистента) — для больших договоров указывайте нужный фрагмент или раздел.
- Ассистент **не загружает и не удаляет** файлы в реестр документов без ваших действий в UI.

## 4. Типовые сценарии

### 4.1. Заявка на перевозку из текста или файла

**Кто:** чаще **Галя** или **Джарвис**.

**Сценарий:**

1. Опишите перевозку текстом **или** приложите PDF/DOCX заявки клиента.
2. Попросите: «Создай черновик заявки» / «Заполни мастер из этого файла».
3. Ассистент создаёт **черновик intake** и может **открыть мастер нового заказа** с предзаполненными полями.
4. **Обязательно проверьте** все поля (заказчик, маршрут, груз, ставки) и нажмите **Сохранить** в мастере.

Черновик — это подсказка системы, не готовый заказ. Подробнее — [Регламент оформления заявки](order-application-basic-terms-regulation.md).

Альтернатива без ассистента: **Новый заказ → Заполнить из заявки заказчика** — см. [Документы](documents-user-guide.md#4-заполнить-из-заявки-заказчика-новый-заказ).

### 4.2. Заказ, документы, задачи

- «Покажи заказ …», «Какие документы по заказу …», «Добавь заметку …», «Создай задачу …» — при наличии прав и номера/id.
- Список документов ассистент **читает** из CRM; подписанный скан **прикрепляете вы** на вкладке «Документы».

### 4.3. Базовые условия договоров-заявок (Юрик)

**Где в UI:** **Настройки → Шаблоны печати → вкладка «Базовые условия»**.

**Стороны:**

- **Заказчик (customer / cp)** — условия в заявке/договоре с заказчиком.
- **Перевозчик (carrier / dp)** — условия с перевозчиком.

**Область:**

- **Общие** — для всех контрагентов данной стороны, если нет переопределения.
- **Контрагент** — только для выбранного контрагента (перекрывает общие при печати).
- **Заказ** — индивидуальные условия на вкладке «Нормативы / штрафы» (не путать с глобальными базовыми).

**Примеры запросов Юрику:**

- «Покажи базовые условия перевозчика»
- «Сделай для заказчика по аналогии с перевозчиком»
- «Почему пункты не попали в черновик DOCX?» (диагностика шаблона)

**Права:**

- **Прямое сохранение** глобальных условий — администратор / область «Настройки системы».
- **Менеджер** — заявка на согласование изменений для контрагента (руководитель утверждает в CRM).

Формат пунктов и процесс изменений — в [регламенте](order-application-basic-terms-regulation.md).

### 4.4. Книга продаж

**Галя** может искать и цитировать статьи Книги (скрипты, регламенты, инструкции), если у роли есть доступ к модулю помощника продавца.

После ответа можно оставить **👍 / 👎** — оценка помогает улучшать статьи (аналитика качества Книги).

### 4.5. Контрагенты и СБ (Страж)

- Поиск контрагента, краткий разбор scoring и флагов риска.
- Страж **не блокирует** сделку автоматически — решение за сотрудником СБ или руководителем.

## 5. Что ассистент не делает

| Действие | Почему |
| --- | --- |
| Подписывать документы от вашего имени | Юридически значимые действия — только человек |
| Гарантировать юридическую чистоту формулировок | Рекомендации Юрика — с оговоркой «требует проверки» |
| Обходить лимиты роли или видимости заказов | Доступ = ваши области в CRM |
| Молча менять заказ, контрагента, глобальные условия | Значимые изменения — только по явному запросу и в рамках прав |
| Читать произвольные файлы с диска | Только то, что вы приложили или что есть в CRM |

Если инструмент недоступен, ассистент должен **честно сказать** об этом и предложить путь через UI или коллегу с нужными правами.

---

## 6. Оценка ответа и ошибки

- **Палец вверх / вниз** под ответом — обратная связь по качеству (особенно для статей Книги).
- При сбое AI (лимит, таймаут) — повторите запрос короче или без больших вложений.
- Технические сбои распознавания заявки — см. администратора (OCR, `ORDER_INTAKE_OCR`).

---

## 7. Внешние агенты (Cursor, интеграции)

Те же инструменты MCP доступны **вне браузера CRM**, если администратор выдал **токен Sanctum**. Command bar в CRM использует те же данные, но **без отдельной настройки «Связи MCP»** для каждого инструмента — панель ассистента работает по правам пользователя.

Для разработчиков: список tools — в технической документации MCP CRM.

## 8. Шпаргалка

| Задача | Персона | Действие |
| --- | --- | --- |
| «Куда нажать» / общий вопрос | Джарвис | Текст в command bar |
| Заявка из письма или PDF | Галя | Скрепка + «создай черновик заявки» → проверить мастер |
| Базовые условия cp/dp | Юрик | «Покажи / измени условия перевозчика» или UI в Настройках |
| Условия для одного контрагента | Юрик + руководитель | Заявка на согласование, не прямое сохранение (менеджер) |
| Риск контрагента | Страж | «Проверь контрагента …» |
| Прикрепить подписанный скан | — | Заказ → Документы (не через ассистента) |
