# Контур сверки: заказ → реализация → счёт → платёж

> Статус: дизайн зафиксирован 2026-08-11; sync номера счёта — в коде (`one-c:sync-invoice-numbers`).  
> Связано: `docs/payment-match-token-design.md`, мост 1С, M4.1/M4.2.

## Решения

1. **Счёт** в 1С создаётся на основании **реализации**, которую инициирует CRM. Позже создание счёта может переехать в CRM — модель матчинга та же (номер счёта в CRM).
2. **Входящие** матчим по номеру счёта (`payment_schedules.invoice_number` / `orders.invoice_number`), не по прямой связи платёж↔реализация (в OData `Сделка` пустая; связь идёт через `СчетНаОплату_Key`).
3. **Исходящие** — обязательный токен/`CRM:…` / номер заявки в назначении (см. payment-match-token).
4. **Прочие** платежи — автообучение правил разноса.
5. Sync номера счёта: CRM опрашивает реализации **раз в 12 часов** (создание счёта после реализации может быть >1 дня; оплата после счёта обычно ≥12 ч).

## As-is в 1С (проверено OData)

| Факт | Значение |
| --- | --- |
| Платёж.`РасшифровкаПлатежа.Сделка` | почти всегда пусто |
| Платёж.`РасшифровкаПлатежа.СчетНаОплату_Key` | часто заполнен (входящие) |
| Реализация.`СчетНаОплатуПокупателю_Key` | часто заполнен |
| Filter платежей по счёту | OData `any` по табличной части **работает** |

Цепочка: **реализация → счёт → поступления с этим счётом**.

## To-be CRM

```text
Заказ CRM
  → Реализация 1С (уже есть)
  → Счёт покупателю в 1С (бухгалтер / позже CRM)
  → Sync 12ч: Number счёта → orders.invoice_number
                 + открытые customer payment_schedules.invoice_number
  → Банк / УУ: матч по «счёт №…» (уже есть MatchingService)
```

Исходящие: стоп без токена; клиент/менеджер не при чём.

### Частичные оплаты и несколько счетов

- Один счёт / несколько поступлений — график с `remaining_amount` уже умеет.
- Один ПП на несколько счетов — клиент пишет номера в назначении; иначе split в Reconcile. Не обещать авторазбор без номеров.

## Код

| Кусок | Роль |
| --- | --- |
| `OneCInvoiceNumberSyncService` | realization ref → invoice Number → CRM |
| `one-c:sync-invoice-numbers` | artisan + schedule `twiceDaily(1, 13)` (~12ч) |
| `OneCBpClient::getBuyerInvoice` | OData `Document_СчетНаОплатуПокупателю` |
| `ManagementAccountingMatchingService` | матч по `invoice_number` (as-is) |
| `PaymentMatchToken` | исходящие |

## Non-goals сейчас

- Создание счёта из CRM (фаза 2)
- Двусторонний sync оплат 1С↔график без человека
- Авторазбор мульти-счёт без номеров в назначении

## Приёмка

1. У заказа с реализацией и счётом в 1С после sync в CRM появляется номер счёта на заказе и на строках графика заказчика.
2. Входящий платёж «оплата по счёту №…» матчится на график (confidence высокий).
3. Повторный sync идемпотентен (не затирает ручной номер тем же значением; не плодит дубли).
4. `ONE_C_ENABLED=false` / нет счёта у реализации — тихий skip.
