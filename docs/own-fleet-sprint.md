# Спринт: интеграция «Собственный парк» с заказами

Цель: выбор **«Свой транспорт»** на плече/слоте заказа, учёт **примерной** и **фактической** стоимости в «ставке перевозчика», операционный модуль парка (рейсы, затраты, эффективность, ТО/заправки) без отдельного оформления заказа.

---

## Принципы

1. **Заказ** — единая точка оформления (плечи, split, `contractors_costs` → `carrier_rate` → `delta`).
2. **Модуль «Собственный парк»** — рейсы, фактические затраты, парк, эффективность, заправки/ремонты.
3. **Заказчик** оплачивает перевозку **на весь рейс** (один `customer_rate` на заказ; на плече может быть несколько слотов исполнения).
4. Контрагент **«Собственный парк»** (виртуальный, `is_own_company` / отдельная запись) — для отчётов и привязки строк `contractors_costs`.

---

## Заказ: выбор перевозчика

### UI мастера

- В поиске перевозчика на плече / в слоте split — закреплённая опция **«Свой транспорт»**.
- При выборе:
  - `contractor_id` → ID контрагента **«Собственный парк»**;
  - флаг `execution_mode: own_fleet` в metadata плеча/слота;
  - поля **ТС / водитель** (как сейчас, через `fleet_vehicle_id`, `fleet_driver_id`);
  - **Примерная стоимость** (ручной ввод в строке `contractors_costs.amount`) — для планирования маржи до рейса;
  - опционально `fleet_trip_id` после создания рейса в модуле парка.

### Смешанные схемы (международка)

- На одном плече: split — слот 1 внешний перевозчик, слот 2 «Свой транспорт».
- **«Ставка перевозчика»** в гриде = сумма **всех** строк `contractors_costs` (внешние + свой парк).

### Синхронизация факта

| Этап | Источник `amount` в `contractors_costs` |
|------|----------------------------------------|
| Черновик / план | **Примерная стоимость** (ввод в мастере) |
| Рейс завершён в модуле парка | **Факт** = `fleet_trip.total_cost` → перезапись строки заказа, пересчёт `carrier_rate`, `delta` |

Не блокировать сохранение заказа без завершённого рейса.

## Документы и чек-лист (раздел 5)

Для заказов, где **все** слоты перевозчика — `execution_mode = own_fleet` (собственный парк):

- **Обязательны только:** заявка заказчику, закрывающие заказчику (УПД / акт + счёт-фактура), ТСД (ТН / ЭТрН / CMR).
- **Не требуются:** заявка и закрывающие перевозчику, закрывающие подрядчикам по доп. расходам.
- Закрывающие заказчику **обязательны даже при оплате наличными** (исключение из общего правила «нал — без УПД»).

Для плеч/слотов с `execution_mode = own_fleet` в **смешанных** заказах (есть и внешний перевозчик):

- **Не показывать** слоты печатных форм «заявка перевозчику» / закрывающие по перевозчику в вкладке «Документы» мастера заказа.
- **Не включать** в `OrderDocumentRequirementSlotBuilder` правила `carrier_request` и `carrier_closing` для этих слотов.

Документы **заказчика** и **internal** (ТН/ЭТрН) — по общим правилам, кроме упрощённого чек-листа выше для «только свой парк».

Точки правок:

- `app/Support/OrderDocumentRequirementSlotBuilder.php` — пропуск carrier-слотов own_fleet;
- `resources/js/support/orderPrintFormSlots.js` / `OrderWizardDocumentsTab.vue` — скрытие carrier print-слотов;
- `orderDocumentRequirementSlots.js` — согласованная фильтрация на фронте.

## Модуль «Собственный парк»

Расширение текущего автопарка (`fleet_vehicles`, `fleet_drivers`).

### Сущности (новые)

**`fleet_trips` (рейс)**

| Поле | Назначение |
|------|------------|
| `order_id` | Заказ |
| `order_leg_stage` | Плечо |
| `carrier_slot` | null \| 1 \| 2 (split) |
| `fleet_vehicle_id`, `fleet_driver_id` | Ресурсы |
| `status` | planned / in_progress / completed / cancelled |
| `estimated_cost` | Копия плана из заказа (опционально) |
| `total_cost` | Факт после закрытия |
| `planned_km`, `actual_km` | Эффективность |
| `started_at`, `completed_at` | Сроки |

**`fleet_trip_cost_lines` (строки затрат)**

Базовые статьи (`cost_category`):

| Код | Название |
|-----|----------|
| `fuel` | Топливо |
| `driver_salary` | Зарплата / сдельная оплата водителя |
| `per_diem` | Командировочные / суточные |
| `toll` | Платные дороги |
| `repair` | Ремонт по рейсу |
| `other` | Прочее |

Поля: `amount`, `currency`, `comment`, `occurred_at`, опционально файл.

**Позже (фаза C):** `fleet_fuel_events`, `fleet_maintenance_records` — с привязкой к ТС и опционально к рейсу.

### Экраны модуля

1. **Рейсы** — реестр, карточка, связь с заказом, ввод фактических затрат, закрытие рейса.
2. **Парк** — ТС, водители (существующие страницы).
3. **Эффективность** — ₽/км, план/факт км, доля рейсов с own_fleet в заказах (отчёт).
4. **Заправки / ТО** — после MVP рейсов.

### API / события

- `POST/PATCH fleet/trips` — CRUD рейса.
- `POST fleet/trips/{id}/complete` — финализация: сумма строк → `total_cost` → синхронизация в `financial_terms.contractors_costs` и пересчёт компенсации заказа.

---

## Контрагент «Собственный парк»

- Одна системная запись в `contractors` (seeder / artisan ensure).
- `is_own_company = true`, фиксированное имя, например **«Собственный парк»**.
- Используется как `contractor_id` в строках `contractors_costs` и для фильтра fleet options (`owner_contractor_id`).

---

## Грид «Заказы»

- Колонка «Ставка перевозчика» — без смены формулы.
- Опционально: индикатор «есть свой участок» + tooltip (внешние / свой парк).
- Подпись в UI при необходимости: «Стоимость исполнения».
