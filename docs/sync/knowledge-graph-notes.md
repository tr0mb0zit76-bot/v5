# Граф знаний: Obsidian vs Hive Mind в CRM v5

> Для vault: `Exchange/CRM/knowledge-graph-notes.md` (копируется скриптом sync).  
> Источник в git: `docs/sync/knowledge-graph-notes.md`

## Короткий ответ

**Да** — «пышный» граф в Obsidian *может* описывать связи между блоками кода, файлами и классами.  
**У нас по задумке** — связи между **функциями продукта** (домены, модули, решения, ограничения), а не AST всего репозитория.

Это разные уровни абстракции; оба полезны, но не заменяют друг друга.

## Три слоя «памяти» в проекте

| Слой | Где | Что хранит | Граф |
| --- | --- | --- | --- |
| **Оперативная** | `Cursor-handoff-latest.md`, чат Cursor | Что сделано в последних сессиях, HEAD, runbook | Нет — лента фактов |
| **Архитектура продукта** | Vault `Exchange/CRM`, `docs/sync/v5-local-*.md` | Заказы, рейсы, УУ, роли, ADR | **Hive Mind:** `component`, `decision`, `interface`, `constraint` |
| **Код** | Репозиторий, IDE, `AGENTS.md` | Классы, маршруты, Vue-страницы | Не визуализирован в vault (поиск / агент по коду) |

## Почему граф Obsidian выглядит богаче

1. **Любая wiki-ссылка `[[…]]`** попадает в граф — заметки, черновики, runbook, дизайн, дубликаты.
2. **Двунаправленные связи** — Obsidian рисует все рёбра между упомянутыми заметками.
3. **Нет фильтра по типу** — unless вы вручную тегируете `#component` vs `#draft`.

Наш `v5-local/00-index` — **курируемое дерево**: десятки узлов, не тысячи файлов `app/`.

## Могли бы ли мы графить код?

Да, если завести заметки вида:

- `[[FleetTripService]]` → `[[Fleet Own Fleet component]]`
- `[[OrderWizardService]]` → `[[Orders]]`

Тогда граф Obsidian стал бы похож на карту модулей **на уровне классов**. Минусы:

- Дублирование git / быстро устаревает без дисциплины;
- Агенту Cursor проще `grep` и `AGENTS.md`, чем 500 заметок;
- Бизнес-вопросы («почему заказ не в Рейсах?») решаются карточкой **Fleet**, а не графом из 40 PHP-файлов.

**Рекомендация:** оставить vault на **продукт + решения + runbook**; в карточках компонентов — таблица «ключевые файлы» (как в `v5-local-Components-Fleet-Own-Fleet.md`). Код-граф — только для сложных подсистем, если реально мешает ориентироваться.

## Cursor «память» vs Obsidian

- **Cursor Memory / прошлые чаты** — эвристика агента, не канон.
- **Канон для второго ПК:** `git pull` + `Cursor-handoff-latest.md` + `sync-docs-to-yandex.ps1`.
- Obsidian — для человека и `@`-контекста в Cursor, не замена тестов и кода.
