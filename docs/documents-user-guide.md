# Документы — инструкция для пользователя

Единое руководство по модулю **Документы** в CRM и связанным инструментам: реестр, вкладка «Документы» в мастере заказа, печатные формы, распознавание заявки, портал перевозчика.

**См. также:** [Мастер заказов](order-wizard-user-guide.md) (раздел 9) · [Регламент работы с документами](documents-regulation.md) · [Ассистенты CRM](ai-assistants-user-guide.md) · [Nextcloud / хранилище](nextcloud-install.md) (для админов) · [OCR заявки](order-intake-ocr-service.md)

---

## 1. Два входа в работу с документами

| Где                                     | Для чего                                                                                        |
| --------------------------------------- | ----------------------------------------------------------------------------------------------- |
| **Меню → Документы**                    | Реестр по всем заказам: бухгалтерия, логистика, журнал ЭТрН                                     |
| **Заказ → вкладка «Документы»**         | Печатные формы, прикрепление подписанных файлов, чек-лист обязательных документов               |
| **Новый заказ → «Заполнить из заявки»** | Распознать PDF/DOCX заказчика и заполнить поля мастера (не то же самое, что «Документы заказа») |

Документ, загруженный в мастере или через реестр, **один раз** попадает в `order_documents` и виден в обоих местах.

## 2. Раздел «Документы» (реестр)

### 2.1. Как открыть

1. Боковое меню → **Документы**.
2. Страница **Реестр документов** — таблица заказов с колонками по типам документов.

**Доступ:** область видимости **«Документы»** или **«Заказы»**. Состав строк = те же заказы, что вы видите в разделе «Заказы» (не «все документы системы»).

### 2.2. Вкладки

| Вкладка           | Назначение                                                                |
| ----------------- | ------------------------------------------------------------------------- |
| **Все документы** | Полный реестр: счета, УПД, акты, заявки, договоры, транспортные документы |
| **Журнал ЭТрН**   | Только заказы с документом типа **ЭТрН**                                  |

Счётчик — число строк в текущей выборке (до ~400 последних заказов по фильтру сервера).

### 2.3. Таблица

- **Фильтр** — по номеру заказа, номеру заказчика, id.
- **Колонки** — скрыть/показать, порядок сохраняется в браузере.
- **Одиночный клик** по подписи в ячейке → предпросмотр файла или экран печатной формы.
- **Двойной клик по строке** → окно **Документы заказа** (полный список + загрузка).

### 2.4. Добавить документ из реестра

**Добавить документ** → заполните:

| Поле        | Обязательно     | Пояснение                              |
| ----------- | --------------- | -------------------------------------- |
| Заказ       | Да              | Из списка доступных вам                |
| Сторона     | Да              | Заказчик / Перевозчик / Внутренний     |
| Тип         | Да              | Счёт, УПД, Акт, **ТН / ЭТрН / CMR / ТСД** (одна группа) и др. |
| Статус      | Да              | Черновик, Ожидает, Подписан, Отправлен |
| Номер, дата | Нет             | Для подписи в таблице                  |
| Файл        | Да при создании | PDF, DOC/DOCX, XLS/XLSX, JPG/PNG/WebP  |

Файл можно перетащить. При превышении лимита размера — предупреждение (лимит зависит от «веса» документа в страницах, см. подсказку в форме).

## 3. Мастер заказа — вкладка «Документы»

Подробный сценарий статусов заказа — в [order-wizard-user-guide.md](order-wizard-user-guide.md#9-вкладка-документы). Здесь — фокус на документообороте.

### 3.1. Структура вкладки

Сверху вниз:

1. **Печатные формы** (зелёные блоки — заказчик, красные — перевозчик)
2. **Прикрепить файл** — drag-and-drop подписанных сканов/PDF
3. **Учёт документов** — чек-лист для статусов «Оплата» и «Завершено»

> **До первого сохранения заказа** печатные формы создать нельзя. Прикрепление файла через API возможно только у сохранённого заказа.

### 3.2. Печатные формы (заявки и договоры из шаблона)

**Шаблоны** настраиваются в **Настройки → Шаблоны печати** (файлы DOCX на сервере CRM). **Файлы заявок и PDF** после финализации хранятся в файловом хранилище CRM (обычно Nextcloud) — путь показан подсказкой на вкладке.

**Создание:**

1. Выберите **Шаблон** в нужном блоке (заказчик / перевозчик / плечо).
2. **Создать в карточке**.
3. В списке появится документ workflow.

**Подбор шаблонов** фильтруется по заказу:

| Условие в шаблоне | Должно совпасть                                       |
| ----------------- | ----------------------------------------------------- |
| Своя компания     | Компания на вкладке «Основное» или шаблон «для любой» |
| Тип перевозки     | Внутренняя / Международная (ВЭД)                      |
| Сторона           | Заказчик / перевозчик                                 |
| Контрагент        | Привязка к конкретному заказчику или перевозчику      |

Выбор шаблона в каждом слоте **сохраняется с заказом** (кнопка **Сохранить** в шапке).

#### Жизненный цикл печатной формы

| Статус          | Что это                                                                |
| --------------- | ---------------------------------------------------------------------- |
| Черновик        | Сгенерированный DOCX, можно править через пересоздание                 |
| На согласовании | Отправлен на согласование (уведомление ответственным — если настроено) |
| Согласовано     | Одобрен, можно загрузить финальный PDF                                 |
| Отклонено       | Нужна правка; укажите причину отклонения                               |
| Подписано (PDF) | Загружен финальный PDF — слот закрыт для правок workflow               |

**Действия:** предпросмотр · скачать DOCX · отправить на согласование · согласовать / отклонить · загрузить финальный PDF · пересоздать черновик · удалить черновик.

Когда **все** печатные заявки по заказу в статусе «Подписано (PDF)», карточка заказа может стать **только для чтения** (баннер в шапке мастера).

### 3.3. Прикрепление подписанных файлов

- Перетащите файл в зону **Прикрепить файл** или нажмите кнопку.
- В модальном окне укажите **сторону**, **тип**, при необходимости **плечо** (если несколько) или **перевозчика**.
- Статус по умолчанию — **Подписан**; файл сразу уходит в реестр (отдельно сохранять заказ не нужно).

**Стороны:** заказчик · перевозчик · подрядчик (из доп. затрат) · внутренний.

Система пытается сопоставить загрузку с **слотом чек-листа** (по типу, стороне, плечу) — так быстрее закрываются обязательные пункты.

### 3.4. Учёт документов (чек-лист)

Число обязательных пунктов **зависит от маршрута, доп. затрат и формы оплаты** каждого контрагента. Список пересчитывается при изменении «Финансов» (форма оплаты заказчика и перевозчиков).

| Группа     | Примеры                                                                                  |
| ---------- | ---------------------------------------------------------------------------------------- |
| Заказчик   | Заявка заказчика; закрывающий документ заказчику (УПД, акт, счёт-фактура…) — **если не наличные** |
| Перевозчик | Заявка перевозчику (по каждому внешнему перевозчику / плечу); закрывающий от перевозчика — **если не наличные** |
| Подрядчик  | Закрывающие по строкам доп. затрат — **если не наличные**                                |
| Транспорт  | **ТН / ЭТрН / CMR / ТСД** — один слот, можно несколько файлов (тип в БД: waybill, etrn, cmr) |

#### Оплата наличными

Если у контрагента форма оплаты **«Наличные»** (`cash`):

- **обязательна только заявка** (заказчику / перевозчику / по доп. затратам — по тому, кому относится слот);
- **закрывающие не требуются** (ни УПД, ни счёт-фактура, ни акт) — пункт в чек-листе **не создаётся**.

Примеры для закрытия сделки (все пункты чек-листа ✓):

| Ситуация | Обязательные документы |
| -------- | ---------------------- |
| Заказчик и перевозчик — наличные | 2 заявки + комплект ТСД (**3** пункта) |
| Перевозчик безнал, два подрядчика (нал + безнал), заказчик безнал | **3 заявки** (заказчик, перевозчик и слот по маршруту при split) + ТСД + **2 закрывающих** (перевозчик и подрядчик с безналом; у «нал» закрывающих нет) |

Форма оплаты берётся из вкладки **«Финансы»**: у заказчика — «Форма оплаты клиента»; у перевозчика — из строк `contractors_costs`; у подрядчика — из доп. затрат.

**Галочка** — когда есть подписанный файл (`Подписан` / `Отправлен`) **или** печатная форма доведена до **финального PDF**.

Режим **«Разбить заявку по плечам»** (вкладка «Основное») увеличивает число слотов заявок заказчика и перевозчиков.

**Свой автопарк:** слоты заявки/закрывающих **перевозчику** для own fleet могут не показываться — см. настройки роли и тип исполнителя на «Маршруте».

## 4. «Заполнить из заявки заказчика» (новый заказ)

На экране **Новый заказ** (до сохранения), блок **Заполнить из заявки заказчика**:

1. Выберите **PDF или DOCX** (желательно с текстовым слоем; сканы — через OCR, если включён на сервере).
2. **Распознать** → превью полей и предупреждения.
3. **Применить к форме** → данные попадают в вкладки «Основное», «Маршрут», «Груз» и т.д.
4. **Проверьте и сохраните** заказ.

Это **не** добавляет файл в «Документы заказа» автоматически. После сохранения при необходимости прикрепите подписанную заявку на вкладке «Документы».

Черновик распознавания (`intake_draft`) можно открыть по ссылке из уведомления или MCP; при сохранении заказа черновик фиксируется для обучения (если включено).

Подробнее для админов: [order-intake-ocr-service.md](order-intake-ocr-service.md).

## 5. Окно «Документы заказа»

Открывается:

- двойным кликом по строке в **реестре**;
- из карточки заказа (если есть кнопка «Документы»).

Внутри: полный список файлов и печатных форм, быстрая загрузка, замена файла, удаление (при правах). Удобно для бухгалтерии без входа в мастер.

## 6. Типы и статусы (справочник)

### 6.1. Типы загружаемых документов

| Тип                                | Когда                                             |
| ---------------------------------- | ------------------------------------------------- |
| Заявка / Договор-заявка / Договор  | Подписанные бумаги (или дублируют печатную форму) |
| **ТН / ЭТрН / CMR / ТСД**          | Транспортные и таможенные (в UI — одна группа)    |
| УПД, Счёт, Счёт-фактура, Акт       | Закрывающие (не требуются при оплате наличными)   |
| Пакинг-лист, Таможенная декларация | ВЭД                                               |
| Прочее                             | Всё остальное                                     |

Заявки **из шаблона** создаются только через **Создать в карточке**, не через «Добавить документ».

### 6.2. Статусы реестра (загруженные файлы)

| Статус    | Смысл                                                            |
| --------- | ---------------------------------------------------------------- |
| Черновик  | Учёт не завершён                                                 |
| Ожидает   | Ждёт подписи / отправки                                          |
| Подписан  | Согласован (закрывает чек-лист)                                  |
| Отправлен | Передан контрагенту / в ЭДО (тоже закрывает ТН/ЭТрН в чек-листе) |

## 7. Связанные разделы CRM

| Раздел                         | Связь с документами                                      |
| ------------------------------ | -------------------------------------------------------- |
| **Контрагенты → карточка**     | Договоры и сканы контрагента (отдельно от заказа)        |
| **Автопарк → авто / водитель** | СТС, права, договоры аренды                              |
| **Портал перевозчика**         | Перевозчик по ссылке загружает документы в заказ         |
| **Финансы**                    | Финансовые документы по заказу (при области «Документы») |
| **Интеграции → 1С Fresh**      | Подтягивание ЭТрН по заказу (если настроено)             |

Документы контрагента **не подставляются** в заказ автоматически — их прикрепляют к заказу отдельно или генерируют из шаблона.

## 9. AI и MCP

В command bar и внешних агентах (при выданном токене):

| Инструмент               | Назначение                             |
| ------------------------ | -------------------------------------- |
| `list_order_documents`   | Список документов заказа по `order_id` |
| `get_order_intake_draft` | Черновик после распознавания заявки    |

Персона **«Юрик»** в ассистенте ориентирован на формулировки и шаблоны; загрузка и удаление файлов через AI **не выполняются** без явного UI-подтверждения.

| Область видимости | Что даёт                                                             |
| ----------------- | -------------------------------------------------------------------- |
| **documents**     | Раздел «Документы», финансовые документы                             |

## 11. Частые вопросы

**Не вижу раздел «Документы» в меню**  
Включите область **«Документы»** (или работайте через заказы с областью **«Заказы»**).

**Заказ не в списке при добавлении**  
Нет доступа к этому заказу в разделе «Заказы».

**Колонка в реестре пустая, в заказе файл есть**  
Обновите страницу; проверьте тип (например «Прочее» не попадёт в «Счёт заказчику»).

**Клик открывает форму, а не PDF**  
Это печатная форма из шаблона — нормальное поведение.

**Плейсхолдер в колонтитуле DOCX — файл не открывается**  
Переменные `${…}` и `{{…}}` в **колонтитулах** шаблона поддерживаются. Если предпросмотр или скачивание черновика падает — обновите CRM до актуальной версии или обратитесь к администратору (шаблон в **Настройки → Шаблоны печати**).

**Не создаётся заявка перевозчику**  
Сохраните заказ; укажите перевозчика на «Маршруте»; для ВЭД включите «Международная» на «Основном».

**Ошибка размера файла**  
Уменьшите файл или разбейте PDF; лимит привязан к оценке числа страниц (подсказка в форме загрузки).

**Распознавание заявки не работает**  
Обратитесь к администратору: OCR sidecar и `ORDER_INTAKE_OCR` на сервере.

**Не хватает закрывающих, хотя оплата наличными**  
Проверьте форму оплаты на вкладке «Финансы». При `cash` закрывающие в чек-лист не попадают — достаточно заявки и ТСД.

**Где физически лежат файлы**  
На сервере CRM / Nextcloud (WebDAV). Пользователю достаточно предпросмотра и скачивания из CRM; прямой вход в Nextcloud не обязателен.
