# Диспозиция — инструкция для пользователя

Документ описывает, как вести ежедневные отметки по заказам **«в пути»**: где машина, комментарии по утру и вечеру, напоминания и показатели для руководителя.

---

## 1. Для чего нужен раздел

**Диспозиция** — один экран со всеми перевозками **«в пути»**: после **фактической погрузки** и до **фактической выгрузки**. По каждому заказу и каждому календарному дню фиксируются:

- **утром** — где машина (обязательно для контроля) и при необходимости комментарий;
- **вечером** — то же самое вторым слотом.

Данные сохраняются в CRM, комментарий попадает в **ленту активности заказа**. Если слот не заполнен к дедлайну, менеджеру создаётся **задача**; при заполнении местоположения задача закрывается автоматически.

Отдельного календаря или карты с GPS нет — работа идёт только в этом гриде.

---

## 2. Как открыть

1. В боковом меню откройте **Планирование**.
2. Выберите **Диспозиция**.

Страница доступна при включённой области видимости **Заказы** у вашей роли. Прямой адрес в системе: `/disposition`.

---

## 3. Какие заказы попадают в таблицу

| Условие | Пояснение |
| --- | --- |
| «В пути» | Есть **фактическая погрузка**, **нет фактической выгрузки** (поля исполнителя или точки маршрута) |
| Удалённые | Не показываются |
| Видимость | **Администратор** видит все такие заказы. Остальные — только заказы, где они **менеджер**, если у роли на заказы не стоит доступ «все» |

Внизу панели грида: *«Показано: N из M. Статус «В пути».»*

---

## 4. Обзор экрана

### Верх страницы

Краткое описание и заголовок **Диспозиция**.

### Панель KPI (над гридом)

Три блока за **сегодня** (часовой пояс компании, по умолчанию Москва):

| Блок | Что показывает |
| --- | --- |
| **Оба слота** | Доля заказов, у которых за день заполнены **и утро, и вечер** (имеется в виду местоположение в обоих слотах) |
| **Средняя задержка внесения** | Насколько позже дедлайна 10:00 / 16:00 в среднем сохраняли ячейки |
| **Утро / вечер** | Процент заполнения местоположения отдельно по утреннему и вечернему слоту |

### Панель грида

| Элемент | Назначение |
| --- | --- |
| Поле поиска с иконкой | Быстрый поиск по номеру заказа, клиенту, маршруту, парку, плановой дате и тексту в ячейках |
| Кнопка с иконкой строк | **Плотность** таблицы (как в других гридах CRM) |
| Счётчик справа | Сколько строк видно после фильтров |

Под таблицей — **горизонтальная полоса прокрутки** (как в гриде заказов), чтобы удобно листать дни.

---

## 5. Структура таблицы

### Строки

Один заказ — одна строка, сортировка по номеру заказа.

### Закреплено слева

| Колонка | Содержимое |
| --- | --- |
| **Заказ** | Номер; фильтр в шапке колонки |
| **Клиент** | Заказчик |
| **Парк** | Свой парк / наёмный / смешанный / — |
| **Маршрут** | Кратко: точка погрузки → выгрузка по маршруту заказа |

### По центру — календарные дни

Шкала дат строится автоматически:

- **слева** — от самой ранней **погрузки** среди незакрытых рейсов (или всех «в пути», если незакрытых нет);
- **справа** — до самой поздней **плановой выгрузки** среди заказов в таблице.

На каждый день — группа заголовка **дд.мм.гггг** и четыре колонки:

1. **Утро — место** (редактируется)
2. **Утро — комм.** (редактируется)
3. **Вечер — место** (редактируется)
4. **Вечер — комм.** (редактируется)

### Закреплено справа

| Колонка | Содержимое |
| --- | --- |
| **План прибытия** | Плановая дата выгрузки заказа (для ориентира и подсветки просрочки) |

### Прокрутка при открытии

При первом открытии **левый видимый край** совпадает с колонкой **сегодняшнего** дня (если этот день есть на шкале). Прошлые дни остаются слева за экраном — к ним можно доскроллить.

---

## 6. Как заполнять ячейки

1. Щёлкните по ячейке **место** или **комментарий**.
2. Введите текст.
3. Завершите ввод (переход на другую ячейку или **Enter**) — данные **сохраняются сразу**, без отдельной кнопки «Сохранить».

**Важно:**

- Для контроля и задач считается заполненным слот, в котором указано **местоположение** (не пустая ячейка «Утро — место» или «Вечер — место»).
- **Комментарий** необязателен; при изменении он дублируется в **ленту заказа** с пометкой даты и слота (утро/вечер).
- Система запоминает **кто** и **когда** внёс запись.

Удобно переходить **Tab** между ячейками в строке.

---

## 7. Просроченные рейсы (подсветка строки)

Строка подсвечивается **розовым фоном по всей ширине** (включая закреплённые колонки и редактируемые ячейки), если:

- в колонке **План прибытия** дата **раньше сегодняшнего дня**.

Так видно, что плановая выгрузка уже прошла, а заказ всё ещё «в пути». Отдельно искать номер заказа не нужно — достаточно прокрутить список строк.

Прошлые дни на шкале дат при этом можно открыть горизонтальной прокруткой влево.

---

## 8. Фильтры и поиск

| Инструмент | Где | Действие |
| --- | --- | --- |
| Фильтр по **заказу** | Шапка колонки «Заказ» | Текст «содержит» |
| Фильтр по **клиенту** | Шапка «Клиент» | Текст «содержит» |
| Фильтр по **парку** | Шапка «Парк» | Выбор из списка |
| Глобальный поиск | Поле над гридом | Ищет сразу по нескольким полям и по тексту в ячейках диспозиции |

Фильтры в шапках и поиск можно сочетать.

## 9. Напоминания и задачи

По расписанию (по умолчанию **10:00** и **16:00**, часовой пояс из настроек компании) система проверяет заказы «в пути»:

- если за **сегодня** не заполнено **местоположение** в утреннем или вечернем слоте — менеджеру заказа создаётся **задача**;
- при сохранении ячейки с местоположением соответствующая задача **закрывается**;
- в **личный кабинет** приходит уведомление о новой задаче.

Задачи привязаны к заказу и слоту, дубликаты на тот же слот не создаются.

---

## 10. Дашборд для руководителя

На **главной** (дашборд) блок **Диспозиция** видят роли **администратор** и **супервизор** (при доступе к заказам). Там те же метрики, что на странице диспозиции: заполнение слотов, задержки, число заказов без полного дня.

Если у вас на дашборде показываются «свои» и «общие» цифры — строка **«Мои: …»** относится только к заказам, где вы менеджер.

Ссылка с дашборда ведёт на страницу **Диспозиция**.

---

## 11. Типичный рабочий день менеджера

1. Утром откройте **Диспозиция** — таблица прокручена к **сегодня**.
2. Пройдите по своим строкам (при необходимости отфильтруйте клиента или воспользуйтесь поиском).
3. Заполните **Утро — место** (и комментарий при необходимости) по каждому активному заказу.
4. Обратите внимание на **розовые строки** — плановая выгрузка просрочена, нужна актуализация статуса или дат в карточке заказа.
5. После **16:00** повторите для **вечернего** слота.
6. Если пришла **задача** из напоминания — заполните соответствующую ячейку; задача закроется сама.

---

## 12. Частые вопросы

**Почему нет моего заказа?**  
Скорее всего статус не «в пути», заказ другого менеджера (при ограниченной видимости) или нет доступа к разделу заказов.

**Почему мало дат слева?**  
Шкала начинается с ранней погрузки незакрытых рейсов; старые дни доступны прокруткой влево.

**Почему KPI нулевой?**  
Нет заказов «в пути» в вашей зоне видимости или за сегодня ещё никто не заполнил слоты.

**Изменил только комментарий — задача не закрылась**  
Задачи завязаны на **местоположение**. Комментарий без места слот «закрытым» не считает.

**Где посмотреть историю комментария?**  
В карточке заказа — **лента активности**.

---

## 13. Связь с карточкой заказа

- **План прибытия** в гриде = **плановая дата выгрузки** в заказе.
- **Маршрут** = первая погрузка и последняя выгрузка по точкам маршрута.
- **Парк** определяется по перевозчикам и признаку своего транспорта на плечах.

Чтобы убрать розовую подсветку, приведите в соответствие факт (выгрузка, статус) и плановые даты в **мастере / карточке заказа**.
