## Фаза 2a — Ingest почты (read-only) ✅

**Цель:** переписка **собирается в CRM под капотом**, пока менеджеры **пишут из Outlook**. Это не дублирование «второго клиента», а **индекс** тех же писем в БД для Ledger, портрета и AI.

### Почему не «ассистент читает папку на сервере»

| Вариант | Работает? | Комментарий |
|---------|-----------|-------------|
| Обход `Maildir` на VDS CRM-сервером | Обычно **нет** | Outlook с Exchange/Microsoft 365 **не кладёт** почту в каталог на вашем VDS; письма в облаке M365 или в PST на ПК менеджера |
| Чтение PST на ПК | **Нет** для серверного job | Нужен агент на каждом рабочем месте — хрупко и не для CRM |
| **IMAP / Graph API** к тому же ящику, что открыт в Outlook | **Да** | Стандарт: CRM и Outlook читают **один** почтовый ящик; дедуп по `Message-ID` / `internet_message_id` |
| SMTP только из CRM | Не обязательно в P0 | Исходящие из CRM уже есть для КП; остальное может идти из Outlook, но **Sent** нужно синхронизировать по IMAP |

**Итог:** «не дублировать IMAP» в смысле «не ставить второй почтовый клиент менеджеру» — верно; для **reg.ru** ingest идёт через **IMAP SSL**. Microsoft Graph снят с backlog (2026-07-09).

| # | Задача | Статус |
|---|--------|--------|
| 2a.1 | `users.mail_imap_secret` + `mail_sync_enabled`, sync при login, cron | ✅ MVP без отдельной `mail_accounts` |
| 2a.2 | `mail:sync` — INBOX + **Sent**, дедуп `internet_message_id` | ✅ cron ~10 мин |
| 2a.3 | `direction` inbound/outbound, `last_inbound_at` / `last_outbound_at` | ✅ |
| 2a.4 | Автолинк + **фильтр по доменам контрагентов** (`contractors.mail_sync_domains`) | ✅ |
| 2a.5 | Ledger: `email_inbound` / `email_outbound` | ✅ |
| 2a.6 | HTML-тело входящих (`body_html`), санитизация | ✅ |
| 2a.7 | Вложения входящих (IMAP → storage) | 🚧 код есть, доработка MIME (ATI и др.) |
| 2a.8 | На вкладке «Портрет» / «Коммуникации» — последние N цепочек | 📋 |
| ~~2a.9~~ | ~~(Если M365) Graph вместо IMAP~~ | ❌ снято — почта на reg.ru, IMAP достаточно |

**Не входит в 2a (фаза 2b):** compose/reply из CRM, флаг «важно» в UI почты, push-уведомления.

**Открытые вопросы:**

- ~~Общий `sales@` + личные ящики~~ → **решено: у каждого менеджера свой ящик** (`mail_accounts.owner_user_id`).
- ~~App Password~~ → **reg.ru: обычный пароль ящика** (отдельные app password, как в Google, обычно не нужны); пароль храним зашифрованным в CRM, вводит менеджер или админ один раз.
- Политика ПД: какие письма не индексировать (личные домены, HR)?

**Инфраструктура (зафиксировано 2026-06):** почтовый сервер **reg.ru** (доменная почта на хостинге). Транспорт ingest — **IMAP SSL**, не обход каталогов на VDS CRM.

**Типовые параметры reg.ru** (уточнить в панели «Почта» → настройки ящика):

| Параметр | Значение |
|----------|----------|
| IMAP-сервер | `mail.<ваш-домен>` или `imap.hosting.reg.ru` |
| Порт | `993`, шифрование SSL/TLS |
| SMTP (для будущего) | `mail.<ваш-домен>` или `smtp.hosting.reg.ru`, `465` SSL или `587` STARTTLS |
| Логин | полный адрес `user@domain.ru` |

Перед разработкой 2a: в reg.ru для **каждого** ящика включить **IMAP** (если выключен) и проверить вход тестовым клиентом (Thunderbird / `openssl s_client`).

**Онбординг ящика в CRM (план UI):**

1. **Логин CRM = email ящика** (`users.email`); пароль входа **совпадает** с паролем почты (осознанный компромисс MVP, позже — отдельный пароль / app password).
2. Отдельная форма «пароль почты» **не обязательна**, если включён sync при входе (см. ниже).
3. Cron `mail:sync` обходит пользователей с `mail_sync_enabled`; sync **INBOX + Sent**.
4. Видимость: менеджер видит переписку **своего** ящика; руководитель — по роли (отдельное правило, не в 2a.1).

**Учётные данные для IMAP (важно для разработки):**

Поле `users.password` — **bcrypt**, его нельзя использовать для IMAP. Даже при «одном пароле» CRM должна один раз получить **plaintext** и сохранить **зашифрованную копию** для фонового sync:

| Момент | Действие |
|--------|----------|
| Успешный **login** | Если `mail_sync_enabled` — обновить `users.mail_imap_secret` (Laravel `Crypt`, APP_KEY) |
| **Смена пароля** в профиле | То же |
| `mail:sync` | `username = users.email`, пароль = decrypt(`mail_imap_secret`) |
| Пользователь не логинился после смены пароля в reg.ru | Sync падает с `last_sync_error` → баннер «перелогиньтесь» |

Таблица `mail_accounts` для MVP **может не дублировать логин**: достаточно `user_id` + общие настройки IMAP reg.ru в `config/mail_sync.php` (host, port, encryption). Либо одна строка `mail_accounts` на пользователя, создаваемая автоматически при первом login.

**Безопасность (минимум для MVP):**

- `mail_imap_secret` в `$hidden`, не отдавать в Inertia/API.
- Не логировать пароли и тела писем в AI audit без политики.
- В журнале решений: отдельный пароль почты — backlog после 2a.

**Критерий фазы 2a:** письма, отправленные из Outlook, появляются в CRM в течение N минут после sync; контрагент по email находится; Ledger лида пополняется.
